# Fase 3 — Criterios de aprobación

## Propósito

Verificar que la Fase 3 esté lista para pasar al design system y luego a arquitectura, sin modificar el documento UX base.

- `fase3_prompts_diseno.md`

## Checklist de producto

- [ ] Existe una única definición del MVP.
- [ ] Compra de catálogo y solicitud personalizada están diferenciadas.
- [ ] No se inventa precio para solicitudes personalizadas.
- [ ] El alcance administrativo está aprobado o diferido explícitamente.
- [ ] Los criterios de éxito de Fase 1 se pueden probar con los flujos definidos.

## Checklist de navegación

- [ ] Home lleva a catálogo y solicitud personalizada.
- [ ] Catálogo soporta búsqueda y categoría.
- [ ] Detalle permite seleccionar variantes y agregar al carrito.
- [ ] Solicitud soporta archivo y ayuda de diseño.
- [ ] El carrito separa productos y solicitudes.
- [ ] Cada tipo tiene su checkout correspondiente.
- [ ] El login no destruye el contexto del usuario.

## Checklist de wireframes

- [ ] Home tiene wireframe desktop y móvil.
- [ ] Catálogo tiene wireframe desktop y móvil.
- [ ] Detalle tiene wireframe desktop y móvil.
- [ ] Solicitud tiene wireframe desktop y móvil.
- [ ] Carrito tiene wireframe desktop y móvil.
- [ ] Checkout tiene wireframe desktop y móvil.
- [ ] Cada vista tiene CTA principal y transición siguiente.

## Checklist de estados

- [ ] Loading definido.
- [ ] Success definido.
- [ ] Empty definido.
- [ ] Error definido.
- [ ] Validación definida.
- [ ] Processing y prevención de doble envío definidos.
- [ ] Producto no disponible definido.
- [ ] Error de archivo definido.
- [ ] Foco y teclado considerados.
- [ ] `prefers-reduced-motion` considerado.

## Checklist visual

- [ ] La propuesta respeta la Fase 2.
- [ ] El dark mode es la referencia principal.
- [ ] El modo claro tiene combinaciones de contraste revisadas.
- [ ] El cian no está aplicado a todos los elementos.
- [ ] Los componentes visuales se pueden convertir en tokens.
- [ ] No hay estética gamer ni efectos que distraigan.

## Criterio final

La Fase 3 se considera lista cuando todos los puntos críticos estén marcados, los seis flujos públicos puedan recorrerse sin ambigüedades y los wireframes desktop/móvil hayan sido revisados antes de iniciar la Fase 4.
